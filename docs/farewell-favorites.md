# 送別用のお気に入り 追加仕様

2026-11-15。ユーザーの追加依頼、Issue #12-1（#14）。既存のルーム内検索・商品と手掛かりの最大3枠・下書き保存は残す。

## 使い方

1. 普段のトップ検索の結果から「送別用のお気に入りに保存」を押す。ルームを作る前でも使える。
2. トップの「送別用のお気に入りを見る」で保存した商品を確認・解除できる。
3. ルームの「お気に入りから選ぶ」で、今回使いたい商品を候補へ追加する。
4. 追加は画面上の変更なので、最後に「入力内容を保存する」でルームの下書きを保存する。

お気に入りは3商品以上を保存可能。3枠制限は、ルームにコピーする商品と手掛かりの合計に適用する。同一商品をルームに重複追加できない。ルームへの追加でお気に入りは消えず、お気に入りを解除してもコピー済みのルーム候補は消えない。

## 今回の保存先と限界

お気に入りはlocalStorageの`giftia.farewell-favorites.v1`に商品情報のスナップショットを保存する。ブラウザー・プロファイル・オリジン（プロトコル、ホスト、ポート）が同じ場合に利用できる。`localhost`と`127.0.0.1`、3000番と3200番はそれぞれ別の保存先。別ブラウザーや別端末へは同期しない。

ログインやユーザーIDの基盤がないため、今回はブラウザー単位。同じブラウザーを共有する人も同じお気に入りを参照でき、ルームの架空参加者切替とは連動しない。これは本人のアカウントへ保存する正式仕様ではない。privateモードや保存データ削除で消える場合がある。

保存が拒否された場合・容量不足・既存データ破損ではエラーを表示し、成功扱いや黙った初期化をしない。通常のタブ間変更はstorageイベントで反映する。ただし別タブで完全に同時に書き込む場合の排他制御や端末間同期は今回の対象外。

共通MySQL・既存検索API・Gift型・ResultCard・A担当基盤は変更しない。お気に入りAPIも追加しない。将来は本人確認と個人の商品保存先をA・Bで合意し、データ移行・権限・価格と在庫の再取得を設計する。

## 商品情報

保存情報は閲覧時の名前・価格など。最新の価格・在庫・納期を保証しない。後続のIssue #16で、[共通DB読取モード](shared-catalog.md)を追加した。このモードではルーム保存時に共通DBで商品を再取得する。demoモードは従来の架空5商品。取得元に存在しない商品・在庫切れはルーム保存で拒否される。お気に入り自体の保存先はブラウザーのまま。

## PRの依存関係

本機能は未マージのPR #13の候補ストックを前提にした派生ブランチ。リポジトリのルールに従い、追加PRのbaseはmainとする。このため#13がマージされるまでは、その8ファイルもmainからの差分に含まれる。お気に入り追加分だけは`git diff cae6164...HEAD`で確認できる。既存PRを無断でマージせず、#13の承認・マージ後に追加PRの差分を再確認する。

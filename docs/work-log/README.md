# 開発の作業記録

2026年11月15日のユーザー指示「今後はやったことをちゃんと残したい」に基づき、実装・確認・未完了事項をこのフォルダーに記録する。チームの既存ルールはAGENTS.mdに従い、Issue・コミット・PRと対応させる。

## 記録する内容

作業単位ごとに `YYYY-MM-DD-作業名.md` を作成し、次を記録する。

- 目的と対応する要求・要件、Issueへのリンク
- 作業ブランチと開始時点のコミット
- 変更したファイルと変更理由
- 実行した確認と実際の結果、必要な証拠へのリンク
- 未確認事項・失敗・次に必要な対応
- コミット・push・PR・レビュー・マージの実施状況とリンク

未実施を実施済みと書かない。作業記録を作っただけではGitHubへの保存は完了していない。ローカル保存・コミット・push・マージを分けて書く。パスワード・トークン・接続文字列・.envの中身は記録しない。

Issueが作成できない場合は、理由と起票用本文を残す。この記録をIssue作成済みとして扱わず、接続復旧後に重複を確認して正式なIssueへ対応付ける。着手条件はAGENTS.mdとユーザーの指示に従う。

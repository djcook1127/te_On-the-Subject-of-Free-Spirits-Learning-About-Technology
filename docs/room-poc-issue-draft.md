# [Back][Front] 相談ルームの作成・保存・表示を実装する

GitHub Issue未起票の草稿。重複Issueを確認した後に起票し、実際の番号を作業ブランチに使う。

## 背景・目的

共同で送別ギフトを選ぶ前提となるルームを作成し、設定を保存・再表示する。2026-11-15にユーザーが最初のPoCの計画を承認。

## 対応する文書 ID

BR-05、FR-01、DR-02。要件定義書の「受け取り期限の入力仕様」と、今回承認した最初のPoCの範囲に対応。

## 完了条件（Done の定義）

- ルーム名・総予算・参加予定人数・受け取り期限・幹事のニックネームを登録する。
- POST /api/roomsで作成し、GET /api/rooms/{room_id}で取得する。
- 作成者を幹事として同時登録する。途中失敗時はルームと幹事の両方の保存を取り消す。
- 受け取り期限に土日・日本の祝日（振替休日・国民の休日を含む）を指定できない。APIへの直接送信でも保存しない。
- 予算ゼロ・人数ゼロ・過去の受け取り期限を受け付けない。
- 一人あたり負担額は総予算÷参加予定人数を切り上げて表示する。
- 再読み込み後も保存した設定を表示する。
- 既存の/api/search、型・ビルドを確認し、結果を作業記録に残す。
- モックでの検証と実DBでの検証は区別して記録する。

決定期限・メンバー参加操作・共有プロフィール・営業日の逆算・支払い記録は、最初の実装には含めない。
